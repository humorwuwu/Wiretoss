# 无账号只读、HTTPS 与“保存到本机目录”

## 无账号只读模式

桌面端「服务设置」里勾选 **允许无账号只读访问**，或把配置里的
`allow_guest` 设为 `true`。

- 未登录访问者可以：浏览共享目录、下载单文件、打包下载、复制到本机目录
- 未登录访问者不可以：上传、新建文件夹、删除、投送；服务端会返回 403，
  不只是前端隐藏按钮
- 如果配置了密码，只读页面右上角会出现「登录」，登录后恢复写权限
- 同一局域网内任何人都能看到共享目录，请只在可信网络里开启

## 保存到本机目录

这个功能依赖浏览器的 **File System Access API**，所以有硬性条件：

| 条件 | 说明 |
|---|---|
| 浏览器 | 桌面版 Chrome 或 Edge（Safari、Firefox、iOS/Android WebView 不支持） |
| 页面 | 必须是安全上下文：HTTPS，或在本机用 `http://localhost` 打开 |
| 目录 | 第一次使用时由用户选择一个本机文件夹，句柄存在浏览器 IndexedDB 中 |

使用流程：

1. 在 `#save-local-btn`（保存到本机）或列表标题的「保存目录」里选择默认目录
2. 勾选服务器上的文件/文件夹
3. 点「保存到本机」
4. 如果目标目录已有同名项，会弹出冲突对话框：
   - **合并并覆盖**：保留已有文件，同名文件覆盖，新文件追加
   - **删除同名项后复制**：先递归删除目标中的同名文件/文件夹，再完整复制；
     会再弹一次不可撤销的确认
5. 复制过程会显示在传输面板里

源文件保留在服务器上（复制，不是移动）。共享目录外的符号链接会被跳过。

## 启用 HTTPS（局域网其他电脑需要）

桌面端「服务设置」里勾选 **启用 HTTPS**，设置端口（默认 8443），重启服务。
HTTP 监听会继续保留，手机和原生客户端不需要改地址。

服务端第一次启用时会在配置目录下生成：

```
~/Library/Application Support/Wiretoss/certs/    # macOS
%APPDATA%\Wiretoss\certs\                         # Windows
```

- `ca.pem`：本地 CA 证书，发给客户端安装
- `ca-key.pem`：CA 私钥，**不要外传**
- `server.pem` / `server-key.pem`：当前局域网地址的服务器证书，每次启动按当前 IP 重新签发

### 在另一台 Mac 上信任 CA

1. 用 HTTP 打开服务端页面，点提示条里的「下载 CA 证书」；或在服务端窗口复制
   `certs/ca.pem` 的路径后拷过去
2. 双击 `ca.pem`，在「钥匙串访问」里找到它，拖到「系统」钥匙串
3. 双击证书 → 信任 → 使用此证书时选择「始终信任」
4. 重新打开 `https://<服务器IP>:8443/`，确认地址栏是安全连接

命令行等价操作（需要管理员密码）：

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain wiretoss-ca.pem
```

### 在 Windows 上信任 CA

1. 下载 `ca.pem`
2. 双击 → 安装证书 → 本地计算机 → 将所有证书放入下列存储
3. 选择「受信任的根证书颁发机构」→ 完成
4. 完全退出并重新打开 Chrome / Edge，再访问 `https://<服务器IP>:8443/`

### 注意事项

- CA 私钥只保存在服务端配置目录，已按用户权限收紧；不要提交、同步或交给别人
- 删除 `certs/` 会生成新的 CA，客户端必须重新安装信任
- 换局域网 IP 不需要重新信任 CA：服务器证书会用同一个 CA 重新签发
- HTTP 仍然是明文；HTTPS 只是为了让浏览器允许写本机目录，并给桌面浏览器加一层传输加密。
  手机原生 App 继续走 HTTP，不受影响
- 手机 App 的 WebView 不支持这个浏览器 API，所以保存到本机目录入口在原生壳里会被隐藏；
  手机仍可使用普通下载/打包下载
